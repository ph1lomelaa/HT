# Hickmet — состояние работ

Обновлено: 16 октября 2026. Основной сценарий — Telegram Mini App; отдельный сайт тоже поддерживается.

## Готово локально

- Исправлен разбор пакетов, людей, отелей, дат; отдельные изменения для каждой комнаты.
- Mini App и сайт в `pligrim_bot/web`: пакет/ручное заполнение → паломники → проживание → услуги → необязательный перелёт → проверка → PDF.
- Дополнительная страница перелёта включается пользователем; ручные рейсы любой авиакомпании.
- Подписанная авторизация Telegram; отдельный сайт подтверждает вход в боте.
- Генерация и фоновая отправка PDF только в чат подтверждённого пользователя; скачивание PDF/ZIP.
- Удалены перечисленные пользователем промотексты и большой промоблок. Главная начинается с карточек оформления.
- Адрес настроен в локальном `.env`: `https://voucherhickmet.duckdns.org`.
- Проверены 102 теста Python и 6 проверок клиентских сценариев Node: отдельное исправление PDF, доступ по владельцу, сроки хранения, все прежние маршруты Air Astana, отдельные PDF перелёта, история документов, массовые правки и переходы по шагам. Доставка в тестах имитировалась.
- Для пяти услуг добавлены переключатели «Включено». Отключение записывает «Не включено», повторное включение восстанавливает описание; проверено отдельным JS-прогоном. Состояние услуг видно на шаге проверки.
- Расширена область имён: каждое полное имя рисуется одной строкой с подбором размера шрифта. Проверены изображения с двумя именами из скриншота и четырьмя длинными именами; отдельные буквы больше не переносятся.
- Карточка комнаты в Mini App: имена на всю ширину, ниже размещение и количество взрослых с общим числом паломников. Отключены визуальные переносы внутри имени; высота поля меняется по числу строк.
- Стартовое меню бота содержит только «Открыть Hickmet · Создать ваучер»; старые сценарные кнопки убраны из нового /start.
- Восстановлено отдельное редактирование в Mini App: «Изменить» рядом с PDF и «Изменить этот ваучер» под новым PDF в Telegram. Редактор загружает одну комнату со всеми исходными условиями, дизайном и перелётом; результат — новый PDF, остальные комнаты и файлы не меняются. Срок доступа 24 часа, только владельцу.
- Подготовлена полная текстовая инструкция сотруднику: docs/HICKMET_USER_GUIDE_RU.txt. Новые кнопки и инструкция описывают обновление, которое ещё нужно получить на сервере после публикации.
- После замечаний по скриншотам: размещение переведено на фирменный список, взрослых — на счётчик −/+, оба элемента высотой 52px; даты, время и длительность также выровнены. Общий состав комнаты показан отдельной строкой. Счётчик проверен на границы вместимости и число детей; на локальном стенде проверено выравнивание в Chrome на компьютере. Повторная попытка мобильной визуальной проверки прервана передачей управления браузером пользователю.
- Для второй страницы добавлены объяснения трёх маршрутов, подсказка по датам первого города/трансферу и просмотр полной программы в диалоге. В инструкции подробно описаны выбор Медина/автобус, Медина/поезд (в готовом шаблоне Джидда на прилёт и вылет), Мекка первой и отличие второй страницы от страницы перелёта.
- Перенесён отдельный сценарий «Ваучер на перелёт»: загрузка из того же расписания Google Sheets, что в старом чате, либо ручной ввод любой авиакомпании; один PDF без отелей/комнат, просмотр, отправка, скачивание, отдельное исправление.
- В обычном ваучере можно загрузить дополнительные рейсы из расписания выбранной группы.
- «Мои документы» на сайте: последние 50 оформлений своего аккаунта за 24 часа; возврат к PDF/ZIP, редактирование отдельного документа, повторная отправка оставшихся файлов и восстановление данных при ошибке.
- На шаге паломников добавлены «Выбрать все», «Снять все» и размещение для выбранных комнат. Таблица соответствия прежних операций чата сайту: docs/WORKFLOW_PARITY.md. Инструкция сотруднику дополнена новыми сценариями.
- Подпись PDF из чата и Mini App: 📄 пакет / 🛏 тип номера · N pax / 👥 имена. Сохраняется при повторной отправке.
- Выбор месяца/таблицы и группы оформлен собственными списками с поиском, фирменной палитрой и мобильной компоновкой. Синтаксис JS проверен; визуальная проверка заблокирована недоступным браузерным backend.
- Скачивание внутри Telegram поддерживает повторные запросы и загрузку частями по ссылке со сроком 90 секунд; проверены HEAD, GET, Range и истечение ссылки.
- В README описаны запуск сайта, обновление через существующий Caddy и откат старого бота; у web-контейнера есть healthcheck.
- Добавлена безопасная команда `python -m pligrim_bot.diagnostics`: список доступных документов и распознанных месяцев, без ключей и строк паломников.
- По последнему запросу показываются только текущий месяц и будущие (Asia/Almaty), в порядке дат; прошлые скрываются автоматически в боте и Mini App, включая смену года.
- Проверка текущих Credentials: доступно 11 документов; после фильтра на октябрь 2026 остаются October 2026, November 2026, December 2026, January 2027.
- Исправленный парсер проверен на 12 реальных листах: 19 пакетов, 58 PDF; 10 незаполненных пакетов блокируются до исправления.

## Что известно о сервере

- Ubuntu 24.04, адрес `65.21.188.181`.
- Caddy работает как Docker-контейнер `caddy`, образ `caddy:2-alpine`, порты 80 и 443 уже заняты им.
- Caddyfile на хосте: `/root/infra/Caddyfile`, внутри контейнера: `/etc/caddy/Caddyfile` (bind mount одного файла).
- Подходящая сеть: `infra_infra_net`; Caddy также подключён к сетям других проектов.
- По последнему серверному выводу: коммит 0df859d получен, bot/web образы собраны, ht-web-1 Healthy, ht-bot-1 Started, старый pilgrim-bot остановлен и restart=no.
- Caddy успешно получил сертификат Let's Encrypt для voucherhickmet.duckdns.org; публичный HTTPS /health ответил {"status":"ok"}. Первоначальная TLS-ошибка возникла до завершения выдачи сертификата; изменение конфигурации TLS не потребовалось.
- По уточнению пользователя JUNE-JULY-AUGUST 2026/27 и RAMADAN/SHAWWAL-2026 добавлены как общие рабочие таблицы, доступные независимо от фильтра старых месяцев; их листы не скрываются из-за неоднозначного года.
- Актуальный способ доставки кода: пользователь публикует изменения в GitHub, на сервере выполняется git pull. Ранее подготовленный архив больше не используется.
- По уточнению пользователя локальный Caddyfile удалён; Caddy остаётся только в инфраструктуре. Compose запускает bot/web и подключает web к `infra_infra_net` по умолчанию.
- Старый бот: контейнер `pilgrim-bot`, образ `pilgrim-bot:latest`. Он ещё показывает старое меню и только июнь.
- В GitHub-коммите `1c1e173` обнаружен ручной фильтр February 2026, December 2025, January 2026 — возможная причина отсутствующих месяцев. В обновлённом коде фильтр задаётся через EXCLUDED_PILGRIM_MONTHS и по умолчанию пуст. Локальный Google-ключ видит 11 документов; полный результат нужно проверить на сервере.
- SSH с ключом `~/.ssh/id_ed25519` требует passphrase. Пользователь вошёл вручную; автоматическое SSH-подключение пока не авторизовалось.
- Секреты, passphrase и приватные ключи не запрашивать в чате, не включать в архив/образ/Git.
